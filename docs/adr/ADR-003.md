# ADR-003 — Busca, Tags e Sumário (2026-08-28)

## Contexto

Plano `plano-2026-08-28-busca-tags-sumario.md` pede 3 features com recursos autorais e sem libs novas: busca na biblioteca e no PDF, notas com tags/cores e sumário por seções. Stack já é Go 1.26 + pgx + PostgreSQL + Electron + React 19 + Vite. `paginas.camada_json` já guarda `palavras {texto,x0,y0,x1,y1}` mas sem `fontSize`. `notas` já tem `texto/pagina/marcacao_id`. Precisamos decidir como fazer busca e sumário sem over-engineering.

Leitura:
- `backend/internal/store/store.go` — `ListPaginas` retorna `camada_json`, `ListArtigos` conta `paginas`
- `backend/internal/pdf/extract.go` — `Word {Texto,X0,Y0,X1,Y1}` e `WidthPx/HeightPx`, sem fontSize no bbox
- `docs/api.md` — contrato atual sem `?busca`, sem `tags`, sem `sumario`

## Decisão

**Busca:** `ILIKE %q%` com `EXISTS` em `titulo/notas.texto/notas.tags/citacoes.autor|chave` + `GET /api/artigos/{id}/busca` que varre `camada_json` em memória (case-insensitive, `pos` bbox). Não criar `pg_trgm` nem `tsvector` agora (YAGNI). Se ficar lento com >1000 artigos, adiciona `CREATE EXTENSION pg_trgm` + `GIN` depois.

**Sumário:** derivado na hora em `GET /sumario`, sem tabela. Heurística: para cada página, agrupa palavras por `y` (linha), detecta linha como título se `len<80` e (`isUpper` ou `regex ^\d+(\.\d+)*\s+[A-ZÁÂÃÉÊ]`) e `x` centralizado ou `len` curto; fallback para títulos comuns (`introdução|metodologia|resultados|conclusão|referências|bibliografia` case-insensitive). Ordena por `pagina` e `y`. Sem `fontSize` não usamos tamanho, só posição e texto. Se não achar nada, retorna `[]` (sem sumário, não erro).

**Tags:** `ALTER TABLE notas ADD COLUMN tags TEXT[] DEFAULT '{}' + GIN`, `PATCH /notas/{id}` com `tags/cor`.

## Consequências

- Busca simples, sem índice extra, fácil de testar; pode ficar lenta com muitos artigos mas é aceitável para v1 e fácil de otimizar depois com `pg_trgm`.
- Sumário sem tabela evita migração e cache; se o PDF tiver layout em colunas a heurística pode falhar, mas retorna vazio sem quebrar e o usuário ainda tem busca.
- Tags como `TEXT[]` permitem `ANY` e `GIN`, sanitiza `,`/`;` no backend.

## Alternativas consideradas

- `tsvector` + `tsquery` — mais rápido para ranking, mas exige trigger e `to_tsvector`, overkill para <1000 artigos.
- Tabela `sumario` com cache — mais rápido para reabrir, mas adiciona escrita no upload e invalidação; YAGNI.
- `fontSize` via `pdftotext -bbox` com `font` — `bbox` do poppler não traz `fontSize` confiável, precisaria parsear `html` com `font` e complica.

## Validação

- `GET /api/artigos?busca=Silva` filtra 3 fontes, `GET /busca?q=atenção` retorna `pagina/pos`, `GET /sumario` retorna `titulo/pagina` para `artigo-teste.pdf` (2 págs) e `DeepSeek 58 págs`.
- Testes: `go vet`, `go test ./...`, `npx tsc --noEmit`.
