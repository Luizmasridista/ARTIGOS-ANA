# ADR-004 — Sessão Ana Bagatinii + Hardening HTTP para GROK (2026-08-28)

Status: aceito | Data: 2026-08-28 | Autor: techlead (via orquestrador)

## Contexto

Plano `docs/planos/plano-2026-08-28-sessao-ana-seguranca.md` pede sessão single-user para Ana Bagatinii com home em `/`, proteção para exposição via GROK (`https://<id>.grok.io → http://127.0.0.1:8734`), brute-force 5/min por IP e hardening HTTP, usando só recursos autorais (Go stdlib + React) e boring tech/YAGNI. Stack atual: Go 1.26 `net/http` stdlib sem framework (`backend/internal/app/routes.go:10`), PostgreSQL `artigos_ana` via `pgx` (`backend/internal/store/store.go:18`), React 19 + Vite (`app/package.json:19`), CORS atual `*` (`backend/internal/app/helpers.go:64`).

Requisitos do plano:
- `POST /api/auth/login` com cookie `ana_session` `HttpOnly Secure SameSite=Strict`, JWT HS256 1h, `GET /api/auth/me`, `POST /api/auth/logout`
- Rate limit 5 falhas/min por IP → `423 Locked` + `Retry-After: 900` (15min)
- Headers `HSTS`, `CSP`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`
- CORS fechado por env `ALLOWED_ORIGIN`/`GROK_ORIGIN` (não `*`), dev `http://127.0.0.1:5173`

## Decisão

**Princípio:** boring tech + YAGNI. Nada de `gin`, `jwt-go`, `redis`, `captcha` ou OAuth agora. Único acréscimo de dependência permitido: `golang.org/x/crypto` para `bcrypt` (justificado abaixo).

### 1. Autenticação single-user
- Tabela `usuarios(id BIGSERIAL, nome TEXT UNIQUE, senha_hash TEXT, criado_em TIMESTAMPTZ)` + seed `Ana Bagatinii` via `INSERT ... ON CONFLICT DO NOTHING` no `store.Open`.
- Senha com `golang.org/x/crypto/bcrypt` (`CompareHashAndPassword`, cost 10). YAGNI: tabela única serve; multiusuário/2FA fica fora (v2 do plano).
- Endpoints: `POST /api/auth/login {nome, senha}` → `200 {ok:true}` + `Set-Cookie` ou `401 {erro:"credenciais inválidas"}` ou `423 {erro:"muitas tentativas", retryAfter:900}`; `POST /api/auth/logout` → `204` + cookie expirado; `GET /api/auth/me` → `200 {id,nome}` ou `401`. `GET /health` e `/api/health` continuam públicos.

### 2. JWT HS256 autoral (sem lib)
- `issue/verify` com `crypto/hmac`+`crypto/sha256`+`encoding/base64` (RawURLEncoding, sem padding)+`encoding/json` — stdlib puro. Header `{"alg":"HS256","typ":"JWT"}`, payload `{sub, nome, exp (now+3600), iat}`.
- Segredo `JWT_SECRET` env (32+ bytes, falha no boot se ausente em prod; dev fallback aleatório com log). Validação: split 3 partes, `hmac.Equal`, `exp > now`, `alg==HS256`.
- Sem `x/jwt` nem `golang-jwt`: ~60 linhas autorais, testável, sem CVE de lib terceira. YAGNI: não precisamos de `kid`, `aud`, refresh token.

### 3. Cookie de sessão
- `ana_session=<jwt>; Path=/; HttpOnly; Secure; SameSite=Strict; Max-Age=3600`. Sem `localStorage`. Em dev (`ALLOW_INSECURE_COOKIE=1`) permite `Secure=false` para `http://127.0.0.1:5173`; em prod sempre `Secure`.
- `requireAuth` middleware valida cookie em toda `/api/**` exceto `/api/health`, `/api/info`, `/api/auth/*`. Sem cookie → `401 {erro:"não autenticado"}`.

### 4. Rate limit brute force
- Em memória `sync.Map` por IP (`attempts`, `firstAttempt`, `lockedUntil`) + persistência `login_tentativas(ip, tentativas, primeira_tentativa, bloqueado_ate)` para sobreviver a restart (mitiga risco do plano §9). Janela 60s, 5 falhas → `423` com `Retry-After: 900` e `bloqueado_ate = now+15min`. Sucesso zera contador. Auditoria na mesma tabela.
- YAGNI: sem Redis, sem token bucket genérico. Limite por IP puro (suficiente single-user); captcha/WAF só se brute force persistir (fora do escopo).

### 5. Hardening HTTP
- Middleware `securityHeaders` em todas as respostas:
  - `Strict-Transport-Security: max-age=31536000; includeSubDomains` (só quando `r.TLS != nil` ou `X-Forwarded-Proto: https` — caso GROK)
  - `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; object-src 'none'; frame-ancestors 'none'` (remove `http://127.0.0.1:8734` do plano — desnecessário com `self`; `unsafe-inline` mantido só para Vite em dev)
  - `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`
- CORS: substitui `helpers.go:64` `*` por allowlist `ALLOWED_ORIGIN`/`GROK_ORIGIN` (ex: `https://abc.grok.io`) + `http://127.0.0.1:5173` em dev; `Access-Control-Allow-Credentials: true`, `Allow-Headers: Content-Type`, `Allow-Methods` igual. Sem env em prod → sem `Allow-Origin` (fechado).

### 6. Frontend (sem libs novas)
- `Home.tsx` em `/` com form Ana/senha, `AuthContext` (`login/me/logout` via `fetch credentials:include`), `PrivateRoute` que checa `GET /api/auth/me`, interceptor `401 → /`. Sem `react-router` extra.

## Consequências

- Sessão stateless (JWT) sem store de sessão; expira em 1h, logout só limpa cookie (revogação server-side fica para v2 se necessário).
- Rate limit perde precisão em deploy multi-instância (não é o caso: binário único em `0.0.0.0:8734`).
- Adicionar `golang.org/x/crypto` é o único `go get` novo; `go vet`/`go test` continuam sem `gin/jwt`.
- `withCORS` com `*` precisa ser corrigido — risco atual de exposição se GROK for público.

## Alternativas consideradas

- **Hash autoral `sha256+salt` vs `x/crypto/bcrypt`:** rejeitado autoral. `sha256` é rápido e sem cost, vulnerável a GPU/brute force; `bcrypt` é boring tech mantido pelo time Go, sem deps transitivas, custo ~100ms. Plano §4 já prefere `x/crypto`; permitir aqui é a exceção YAGNI correta.
- **`golang-jwt/jwt` vs HMAC autoral:** rejeitado lib. Ganha `aud/kid` que não usamos; perde simplicidade e adiciona API surface/CVE. HMAC stdlib é 1 função (`h.Sum256`).
- **Redis/token bucket vs `sync.Map+PG`:** rejeitado Redis. Overkill single-user, adiciona infra; `sync.Map` + tabela PG já cobre restart e auditoria.
- **`pg_trgm`/`tsvector` para brute force:** não aplicável; rate limit não é busca textual.
- **Captcha/WAF:** fora v1 por YAGNI; só se `login_tentativas` mostrar abuso persistente.

## Validação

- Unit: `jwt_issue_verify_test.go` (sign/verify, exp, tamper), `bcrypt_test.go` (hash/compare), `ratelimit_test.go` (5→200, 6ª→423, Retry-After, reset no sucesso, lock 15min).
- API: `POST /api/auth/login` 200/401/423, cookie `HttpOnly; Secure; SameSite=Strict`, `GET /api/auth/me` 200/401, `GET /api/artigos` sem cookie → 401, com cookie → 200, headers `HSTS/CSP/X-Frame-Options` presentes, CORS `Origin: https://evil.com` → sem `Allow-Origin`.
- E2e: `home-auth.mjs` (login Ana → /biblioteca, 401 redirect, 6 tentativas rápidas → 423, logout limpa cookie).
- `go vet ./...`, `go test ./...`, `npx tsc --noEmit`, `npm run build` passam; sem libs novas além de `golang.org/x/crypto`.
