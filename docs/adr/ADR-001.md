# ADR-001: Estratégia de exportação PDF → DOCX

Status: aceito (v2) | Data: 2026-08-27 | Autor: techlead (via orquestrador)

## Contexto

O usuário quer levar artigos em PDF para o Word/Google Docs para editar e anotar lá também. A v1 (páginas como imagem + camada de texto invisível) preservava o visual, mas o conteúdo saía como imagem colada, não editável. O usuário deixou claro: o conteúdo precisa ser EDITÁVEL.

## Opções

1. **Páginas como imagem + camada invisível** (v1): fiel visualmente, mas conteúdo não editável. Rejeitada pelo usuário.
2. **Reconstrução de texto formatado** (escolhida, v2): extrair o texto com fonte e tamanho via `pdftotext -bbox-layout` e remontar em parágrafos editáveis no DOCX.
3. **Conversão via LibreOffice**: dependência pesada, resultado inconsistente. Rejeitada.

## Decisão (v2)

- Cada linha do PDF vira um **parágrafo editável** no DOCX, com fonte (`w:rFonts`), tamanho (`w:sz`) e cor (`w:color`) extraídos do layout.
- **Quebra de página** entre páginas do artigo e antes da seção de notas.
- **Notas do usuário** entram no final, com âncora "Página N".
- **Sem imagens coladas como conteúdo.**

## Consequências

- Texto 100% editável no Word e no Google Docs.
- Layout visual (colunas, tabelas, posicionamento absoluto) não é reproduzido; a ordem de leitura é.
- Marcas d'água em texto são preservadas como texto editável. Marcas d'água gráficas (imagens/vetores) não são exportadas na v2; pode entrar como marca d'água de fundo numa v3 se o usuário pedir.
- Arquivo final leve (só XML).
